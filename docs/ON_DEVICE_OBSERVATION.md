# Android / iOS 端侧观察 MVP

## 能力边界

“端侧观察”默认关闭，仅在家长主动开启后使用前置相机。它检测的是可观察代理信号，不等同于“认真”“注意力”或医学结论。

- 是否检测到面部
- 面部在画面中的位置
- 面部占画面比例（仅用于距离过近/过远提示）
- 头部左右转动、侧倾和俯仰角度
- 是否出现多张面部

不做人脸身份识别，不建立人脸模板，不录像，不生成照片，不上传原始帧。相机输出以 RGBA 内存帧传入端侧插件，每 3 秒最多分析一次。

## 平台实现

- Android：`android.media.FaceDetector`，输入帧缩放至最多 480 px 宽并转换为 RGB_565；自动尝试 0°、90°、180°、270°，选择可信度最高的人脸，返回眼距估算的面部占比、中心点、Euler 角和置信度。
- iOS：Apple Vision `VNDetectFaceRectanglesRequest`；返回最大面部的归一化包围框、yaw、roll、pitch 和置信度。
- 非 Android/iOS 平台：插件明确返回 `supported=false`，页面保留普通番茄计时。

## 当前产品阈值

阈值位于 `pages/companion/companion.uvue`，需要根据不同年龄、设备摆放和真机样本继续校准。

| 信号 | MVP 阈值 | 提示 |
| --- | --- | --- |
| 无面部或低置信度 | `confidence < 0.30` | 回到镜头前 |
| 距离过近 | `faceScale >= 0.58` | 向后坐一点 |
| 过远/偏离中心 | `faceScale <= 0.11` 或中心越界 | 调整位置 |
| 明显偏头 | yaw > 28°、roll > 22° 或 pitch > 25° | 放松并摆正头部 |
| 提醒节流 | 同类异常提示至少间隔 15 秒 | 避免打扰 |

结果页和“星小屋”只保存汇总秒数与提醒次数：观察秒数、稳定在屏秒数、离开秒数、过近秒数和偏转秒数。

## 真机验证

1. 使用 HBuilderX 4.61 或更高版本重新运行到 Android/iOS 真机；首次开启时允许相机权限。
2. 在“星陪伴”选择 1 分钟，开启“端侧观察”并开始。
3. 正对、靠近、移出画面、明显转头各保持 6–9 秒，确认状态文字发生变化。
4. 确认提醒间隔不少于 15 秒；暂停时状态不再累计。
5. 完成后检查端侧观察摘要，再到“星小屋”检查“稳定在屏”比例。
6. Android 拒绝权限、iOS 拒绝权限后应继续普通计时，不得阻断陪伴流程。

注意：新增 UTS 原生混编代码和权限描述后，应重新制作/运行基座，不能只依赖旧基座热更新。

## 上半身坐姿检测升级方案

Android 与 iOS 均可引入 ML Kit Pose Detection 基础版，在设备端取得同一套 33 个人体关键点。Android 依赖 `com.google.mlkit:pose-detection:18.0.0-beta5`，iOS 依赖 `GoogleMLKit/PoseDetection 8.0.0`。两端都使用实时流模式并丢弃处理不过来的旧帧。

产品侧不直接把单帧结果称为“坐姿正确/错误”，而是先取得 5 秒自然坐姿基线，再根据连续 6 秒以上的偏离给出温和提醒：

- 头部侧倾：双耳连线或头部角度相对基线偏差过大。
- 身体左右倾斜：双肩连线倾角持续超过基线约 8–10°。
- 含胸/前倾：耳—肩—髋的夹角或深度比例持续偏离基线；只有肩、髋关键点置信度足够时才判断。
- 距离过近：继续使用面部占比或肩宽占比，避免人体模型不可用时完全失去提醒。
- 关键点缺失：标记为“无法判断/请调整设备”，不得归类为错误坐姿。

前置摄像头必须至少拍到头部、双肩和上半身；若髋部不在画面中，系统只能提供“头颈与肩部姿态提醒”，不能可靠判断驼背。所有异常都需要时间窗口、置信度门槛和提醒冷却，不能用单帧触发。

该 SDK 当前仍为 Beta。基础版预计增加 Android 约 10.1 MB、iOS 最多约 29.6 MB；引入后必须重新制作两端自定义基座，并在儿童、眼镜、弱光、不同肤色和不同设备摆放条件下校准阈值。
