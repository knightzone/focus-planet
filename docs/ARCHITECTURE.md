# MVP 技术结构

## 领域结构

```text
ChildProfile
  -> AgeBand
  -> DailyPlan
  -> TrainingGame
  -> TrainingRecord
  -> DimensionReport
```

每个游戏只能有一个主要维度，可以附加次要维度。成长分数只计入主要维度，避免同一局训练被重复计算。

## 当前本地数据

- `focus_planet_profile`：儿童昵称、出生年月、动态年龄、性别、内置头像与服务端档案 ID
- `focus_planet_records`：游戏、维度、分数、正确率、反应时间与完成时间
- `focus_planet_companion_records`：陪伴模式、计划时长、实际专注秒数、休息完成情况、自检提醒次数与完成时间（最多保留最近 100 条）

正式版应为本地记录增加 schema 版本，并在登录后与服务端进行增量同步。

## 服务端接口规划

2026-09-04 已形成 V1 服务端接口讨论稿，覆盖服务端每日 5 项计划、跨天续做、单项最佳成绩、多日与整体报告，以及资源包异步补全。详见 [SERVER_API_DESIGN.md](SERVER_API_DESIGN.md)。当前本地每日 3 项和按游戏难度逻辑保留为原型实现，正式接入时以服务端计划与计划级难度快照为准。

2026-09-04 一级信息架构调整为三 Tab：`星训练` 保留今日计划和五维训练，`星陪伴` 承载训练以外的番茄节奏、坐姿与在屏提醒，`星小屋` 统一承载成长报告、训练历史、档案和设置。Tab 图标复用蓝兔与黄猫两位主题角色，并增加两位角色共同居住的星形小屋。

2026-09-04 陪伴 MVP 已接入本地计时状态机：支持屏幕学习、桌面作业、阅读三种模式，1 分钟真机快测及 10–25 分钟常规时长，包含暂停/继续、提前完成、自动休息、跳过休息、坐姿自检提示和本地完成记录。“我的”页展示最近一条陪伴与累计轮次/分钟。

2026-09-04 Android/iOS 已增加可选端侧观察。`camera` 组件提供前置相机 RGBA 帧，页面每 3 秒抽样一次；Android 插件使用系统 `android.media.FaceDetector`，iOS 插件使用 Vision `VNDetectFaceRectanglesRequest`。插件只返回面部数量、画面占比、中心位置、头部角度和置信度，原始帧不写文件、不进入本地记录。产品层只称“稳定在屏/距离/偏转”，不输出医学或注意力诊断。

## 游戏扩展约定

新增游戏时：

1. 在 `utils/catalog.uts` 增加游戏元数据。
2. 在 `pages/game/` 增加对应页面或复用通用游戏引擎。
3. 训练结束统一写入 `TrainingRecord`。
4. 报告页只通过 `dimensionId` 聚合，不依赖具体游戏实现。

## 评分原则

MVP 只保存原始指标和演示分数。正式版需保留正确率、遗漏、误触、反应时间及其离散程度，再基于同年龄段和个人基线生成成长反馈。不要把游戏分数包装为医学或智力结论。
